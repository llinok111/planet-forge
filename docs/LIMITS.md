# 限制与取舍

一份"没有限制"的说明通常是没测过。以下每一条都是实测或代码结构上的客观边界。

---

## 1. 导出

### 1.1 云、大气、星空不进入 GLB

**现象**：导出的 GLB 只含位移地形 + 行星环。

**原因**：这三个子系统的全部外观来自运行时注入的着色器（散射积分、3D 噪声覆盖率、点精灵形状）。glTF 没有"运行时注入着色器"的机制，导出后它们会是空白几何体。

**为什么不做替代方案**：
- 烘焙成贴图会退化成"贴图球"，与本项目的主张冲突。
- 用 glTF 的 `KHR_materials_*` 扩展需要写自定义扩展，主流查看器不认。

**缓解**：场景 JSON 记录全部参数，可在本应用内完整复现同一画面。

### 1.2 GLB 顶点色是近似

导出时按与片元着色器**相同**的分带逻辑烘焙顶点色（`io.js: bakeBiomeColor`）。但片元版有 `dFdx/dFdy` 求出的逐像素坡度，顶点版只能用顶点法线近似。陡崖附近的色带边界会有差异。

### 1.3 导出不含层级动画

行星自转角度会被写入 GLB 的根节点旋转（`group.rotation.y`），但云层漂移、海洋波动这类时间动画不导出。

## 2. 渲染

### 2.1 大气是单次散射近似

- 没有多次散射：浓密大气（`atmoDensity` 很低时）会显得比真实情况暗。
- 没有行星阴影软边：晨昏线是一条 `smoothstep`，物理上应有 2–3 度的半影过渡。
- 夜侧辉光强度是**经验标定值**（`uAmbientSky × pow(limb,2.5) × 0.55`），不是物理积分。它的作用是不让夜侧边缘与深空无法区分。

### 2.2 行星环是零厚度圆环

环粒子的垂直厚度未建模。边缘视角（`ringTilt` 接近 0）下环面是一条数学上的线，真实行星环会有一条有厚度的亮线。

环的阴影投影是解析近似：把环上一点投影到行星赤道平面判断是否被行星本体遮挡，不是光线追踪。

### 2.3 云层在极点有轻微拉伸

云层用 `SphereGeometry` 的 UV 球（128×96），虽然噪声在片元里按 3D 坐标采样（所以没有纹理接缝），但球体网格本身在极点三角形更密，细小的锯齿在极点可见。

### 2.4 无 LOD

整颗行星一个细节级别。近景需要手动切 L6（40962 顶点），再靠近看网格边缘仍是硬的。

## 3. 地形

### 3.1 热力侵蚀不是水力侵蚀

实现的是 talus relaxation（碎石坡松弛）：把超过休止角的坡度物质转移到最低邻居。能得到碎石坡、平坦谷底、圆润的山脊，**但不产生树枝状水系**。

要做水力侵蚀需要：排水网络构建 + 流量累积 + 河道下切，成本是当前侵蚀的 10 倍以上，且对细分级别敏感（低细分下河道会断）。取舍是保留热力侵蚀。

### 3.2 板块是 Voronoi 近似

板块由图上多源 BFS 生长而成，不是真正的 Voronoi 图，也不是物理模拟。能保证：连通、面积均衡（最大/最小 < 4×）、边界不规则。不能保证：板块形状像真实板块（真实板块有细长的俯冲带）。

### 3.3 没有"真实的"海平面物理

海平面是排序后的分位数，不是等势面。所以：

- 大陆架不会自动形成（浅海宽度不由地形决定，由 `snowLine` 之外的参数无关）。
- 内陆湖无法产生（没有封闭洼地的水位平衡）。

### 3.4 高度场归一化的副作用

为了让参数可比，构造项被归一化到固定振幅预算。副作用：改 `plateCount` 会同时改变整体起伏的**绝对**尺度。这是刻意的取舍——否则两套参数的高度无法比较。

## 4. 工程

### 4.1 重建是同步的

`regenerate()` 在主线程同步执行。L5 约 71 ms，L6 约 326 ms。遮罩能盖住空窗，但主线程确实被占用。真正的解法是 Web Worker + Transferable，代价是数据结构要改成可转移（`Float32Array` 已经满足，但 `Map` 缓存和 `Set` 不行）。

### 4.2 参数面板不是通用的

`ui.js` 只支持 `seed / range / color / toggle` 四种控件。没有 `select`、`vector2`、`vector3`、渐变编辑器。`params.js` 里定义了 `select` 类型但 UI 未实现——这是一个已知的未完成项。

### 4.3 URL 长度无上限

全部参数非默认时 URL 约 1.2 KB。主流浏览器没问题，但通过社交平台分享时可能被截断。没有做压缩编码。

### 4.4 移动端只做了不溢出

做了：面板宽度自适应、隐藏 HUD、底栏改为纵向、无横向滚动。
没做：触摸手势优化（双指缩放用 OrbitControls 默认行为）、低端设备自动降级细分级别、功耗/发热控制。

## 5. 测试手段的局限

### 5.1 视觉验收是像素测量，不是人眼

本项目开发环境无法把截图交给视觉模型，所以画面验收表达为像素级断言（`scripts/review-shots.mjs`，34 项）。这能抓住"有没有辉光""昼夜差是否够大""预设色调是否真的不同"，但抓不住"好不好看"——构图、色彩和谐、山脊是否有美感，都不在断言范围内。

**补救**：`docs/images/` 下的 7 张截图可以人工查看，配合 `capture-meta.json` 里记录的几何与参数。

### 5.2 软件渲染是性能基线，不是性能结论

全部截图与 e2e 在 SwiftShader（CPU 模拟 GPU）下完成。它证明"正确性"，不证明"流畅度"。文档中所有 fps 相关描述都标注了这一点。

### 5.3 e2e 依赖 dev server

`npm run test:e2e` 不会自己启动服务器。CI 里需要先起 `vite` 再跑，或用 `vite preview` 跑构建产物（更接近真实部署）。

## 6. 有意不做的事

| 功能 | 为什么不做 |
|---|---|
| 大气体积云 | 与云层子系统职责重叠，且成本是当前云层的 20× |
| 城市灯光 | 需要人口分布模型，属于另一个问题域 |
| 生物群系植被网格 | 上游有 `grass.js`/`scatter.js` 可复用，但与"从轨道看星球"的场景无关 |
| 行星系统（多颗行星 + 轨道） | 需求是单颗星球生成器；多体需要完全不同的相机与尺度体系 |
| 物理模拟板块漂移 | 时间尺度上无意义（百万年级），且会让种子复现变复杂 |
