### 三个静态守卫为什么存在

它们拦住的是同一类缺陷：**着色器失败不阻塞构建**。游戏引擎编译失败时通常只打一行 console，画面缺一块，而所有像素断言仍然可能通过。v1 就出过两次：

- 环带着色器有个类型错误（`float toCam = normalize(vec3)`），整块环带没渲染，但容器把"环带已挂载"报成成功。
- `uAmbientSky` 只加进了 uniforms 字典、没写进 GLSL 声明，整块大气失效，而当时 34 项像素断言**全绿**。

所以现在：

```js
// 每条 uniform 双向核对：JS 有声明 → GLSL 必须有；GLSL 有 → JS 必须传
// 保留字检查：decl 形式 "float patch = ..." 直接报错（patch/sample/class/... 共 35 个）
// 反引号检查：任何含 GLSL 的文件，模板内出现裸反引号即失败
```

**守卫本身也要验证。** `shader-uniforms.test.js` 加完后，我手动移除了 `uniform vec3 uAmbientSky;` 这一行，确认测试确实报出该 uniform 未声明，再恢复。没做过这种反向验证的守卫等于没写。

## 3. 像素审阅（34 项）

```bash
npm run shots                  # 7 张截图 + capture-meta.json
node scripts/review-shots.mjs  # 34 项断言
```

7 个镜头：`hero`（整页含 UI）、`planet-day`、`planet-terminator`、`no-rings`、`ocean-world`、`arid-world`、`l6-detail`。

断言分三类：

**每镜头不变量**
```
盘面半径 > 150 px（符合投影预期）
盘面有色彩分带：色块 > 80  或  （色块 > 55 且 亮度 σ > 18）
盘面与深空背景可区分：|mean − sky| > 6
```

**大气专项**
```
边缘存在辉光：annulus 峰值 > sky + 5
昼侧边缘亮于夜侧（同一镜头比较左右）
```

**预设差异**
```
terminator：左右半盘亮度差 > 10
arid vs ocean：R−B 符号相反（暖 / 冷）
L6 近景方差不低于 L5 中景
元数据交叉核对：hero 顶点 10 242、L6 顶点 40 962、relief > 0.05
```

### 为什么盘面半径来自元数据而不是图像检测

试过四种检测法，都有具体失效场景：

| 方法 | 失效原因 |
|---|---|
| 中心行扫描 | 行星环横穿同一扫描线，边界落在环上 |
| 从中心向外找第一个"暗"像素 | 背光时盘面比天空更暗，方向判断反了 |
| 亮度阈值 + 连通域 | 背景噪声让掩码膨胀到整帧 |
| 直方图求暗众数当天空 | 求到的是黑位，不是背景色（背景 `#05070d` 本身有值） |

最终方案：**拍摄时**用投影公式 `r = tan(asin(R/d)) / tan(fov/2) · H/2` 记录到 `capture-meta.json`，审阅时直接读。这是唯一在 7 种构图下都成立的方案。

### 天空亮度的取法也踩过三次

| 方法 | 失效 |
|---|---|
| 四角像素 | 会吃到星点 |
| 顶部条带 | 近景构图时顶部在行星内部 |
| 全帧中位数 | 盘面占 60% 时中位数落在行星上 |

最终：四角各取 36×36 的**25 分位**，再取四个值中较暗的两个平均。星点被分位数剔除，盘面触边时也不会污染。

## 4. 本轮发现并修复的真实缺陷

v1 的 14 个（#1–#14），与 v2 新增的 10 个（#15–#24），全部有实测数据。

| # | 缺陷 | 表现 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | 二十面体细分 O(n²) | L5 562 ms，L6 3657 ms | 每插入中点复制整个 `Float64Array` | 预分配精确顶点数 → 21 / 112 ms |
| 2 | 邻接表残留 `-1` | 侵蚀读到无效邻居 | 按每三角形 2 槽位分配再去重 | 先去重无向边再建 CSR，`length === 2E` |
| 3 | 3D Simplex 格点恒为 0 | 球面出现零值斑点 | 四顶点梯度贡献抵消（算法固有） | 采样空间加种子派生的无理偏移 |
| 4 | 陆地占比不精确 | 0.52 → 0.511；0.20 → 0.166 | 侵蚀后海平面未重锚 | 二次定位，误差 < 0.01% |
| 5 | 云量滑块呈开关状 | 0.52 → 37%，0.70 → 88% | fBm 集中在均值，固定阈值 | 分位数反演（线性误差 0） |
| 6 | 银河带未聚簇 | `bandStrength` 无效果 | 挤压后归一化，角度只缩到 81% | 按经度 + 显式小纬度直接构造 |
| 7 | 环带着色器类型错误 | 整块环带编译失败但报"已渲染" | `float toCam = normalize(vec3)` | 删除未使用变量 |
| 8 | 大气均匀笼罩全屏 | 空白天空亮度 103–140 | `tExit=0` → 采样挤在相机附近 | `hit` 因子收敛 |
| 9 | 大气亮度随步数变 | 4/14/28 → 13/109/110 | 累加器随步长缩放 | v2 改为解析光学深度，彻底消除 |
| 10 | 背光侧行星变纯黑 | 盘面亮度 0.6，σ 2.5 | 采样埋在行星体内 | 恢复全弦 + 夜侧下限 |
| 11 | 大气冲刷地表色 | arid 盘面 [213,216,233] | 面朝分量过大 | 面朝分量 0.012 → 0.0025 |
| 12 | `uAmbientSky` 未声明 | 大气失效，像素断言仍全绿 | 只加了 uniforms 字典 | 补声明 + `shader-uniforms.test.js` |
| 13 | e2e 假报"种子不可复现" | 稳定复现（非偶发） | 见下节 | 改为页面内同步重建 |
| 14 | GLSL 模板内反引号 | 报错在几百行之后 | 注释里写了反引号（累计 5 次） | `template-guard.test.js` |
| **15** | **大气渲染目标停在 1×1** | 整帧均匀灰雾，盘面与天空不可区分（角落 [49,86,104]） | `setSize` 有定义但从未被调用 | `renderInto` 与 `resize()` 都同步绘制缓冲尺寸 |
| **16** | **天空射线被乘透射率** | 整帧雾化，四角被点亮 | 合成公式对"无表面"的像素也乘 `T` | 拆成命中行星 / 纯天空两个互斥分支 |
| **17** | **视线方向用硬编码视锥** | 晨昏带相对受光地面错位 | 假定 60° fov，实际 38° | 用相机 `projectionMatrixInverse` + `matrixWorld` 重建 |
| **18** | **`patch` 是 GLSL ES 保留字** | 编译失败，错误指向**使用处**而非声明处 | 用 `patch` 做噪声变量名 | 改名 `broad`；新增保留字守卫（35 个词） |
| **19** | **`attribute` 在拼接块里不生效** | 整块地表着色失败 | three.js 只重写自己处理的源码，拼接块原样到驱动 | 改写成 `in float`，并注释原因 |
| **20** | **细节噪声变成亮度偏移** | 强度升高，高频方差反而**下降**（2.495 → 2.259） | 乘法调制（`c *= 1 + δ`）在大尺度上压平了原有地形明暗 | 改为加性颗粒 + 三倍频分工（颗粒/团簇/宽域） |
| **21** | **排水网完全碎裂** | 239 个汇点、146 个在海平面、最大集水区 42/2562 | 缺洼地填充，每条小沟独立入海 | priority-flood 填充 → 陆地汇点 0，集水区 110 |
| **22** | **`relaxPits` 的"边缘高差"条件** | 合成凹坑填不上（填充率 0%） | 多余条件把对称盆地的真凹坑也排除了 | 删掉条件，回到"低于所有邻居"单一判据 |
| **23** | **`icosphere is not defined`**（重构后） | 页面初始化失败 | `buildMeshes` 拆分时漏了局部变量 | 从 terrain payload 重建局部 `{vertexCount, positions, indices}` |
| **24** | **L6 截图实际是 L5** | 元数据顶点数 10 242 而非 40 962 | 自动 LOD 在 2.4 倍半径处合法降回 L5 | 该镜头显式 `autoLod: false` |

### 缺陷 #13 的三次修复尝试（值得单独记录）

这条失败很有迷惑性：它**稳定复现**（不是 flaky），看起来像产品缺陷，但产品在 Node 与页面里的直调都是正确的。

| 尝试 | 做法 | 为什么错 |
|---|---|---|
| 1 | 调 rAF 延迟的 `regenerate()` 后等 `ready === true` | `ready` 在调用前就是 `true`，等于没等。下一次重建被丢弃 |
| 2 | 重建前手动置 `ready = false` | 置 `false` 与置 `true` 在同一个同步块里完成，`waitForFunction` 立刻返回 |
| 3 | 轮询几何校验和直到"稳定" | **不可证伪**：被丢弃的重建同样表现为"稳定" |
| 最终 | 页面内直接调 `planet.regenerate()`（同步），同一作用域内取签名并返回 | 一次调用对应一次重建，无时序假设 |

结论：**"稳定复现的失败"不等于"产品缺陷"**。判据只能是独立证据——在 Node 与页面内直接调用都能逐位复现，只有走异步包装的路径失败。

### 生产构建暴露的测试假设错误

`exportGLB` 最初通过 `await import('/src/io.js')` 调用。dev server 下能跑，生产构建下模块已打包，路径不存在，整条 e2e 崩溃。改为从 `window.planetForge.exportGLB` 取用。

## 5. 两类我判错过的"缺陷"

诚实记录，因为它们都影响后续判断：

**其一：`relaxPits` 改动 224 个顶点，被我当成"平白无故改地形"。** 实测发现那片地形里**本来就有 224 个真凹坑**（单顶点低于所有邻居），填充是正确行为。是我的测试前提写错了 —— 断言"干净地形不应被改动"用的是真实生成的地形，而它并不干净。改为显式构造合成地形。

**其二：arid 预设色彩分带不足，我起初以为是大气染蓝。** 关掉大气后色块数仍然只有 28，说明问题在预设本身色调过窄（8 个近乎相同的暖褐色）。修法不是调后处理，而是拉开配色跨度（深玄武岩 → 浅砂岩）+ 提高地形起伏。

这两次都指向同一条：**先量，再改；量错对象时，改得越多偏离越远。**
